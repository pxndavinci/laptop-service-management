## Prerequisites

### Standardize repair statuses (seed canonical status list)

**Labels:** `backend`, `prerequisite`

**Context:** The `status` table is free-form — anyone can create any status name. Upcoming features (status filter on the list, dashboard "overdue" and "not delivered" queries) need a known, canonical set to reason about.

**What to do:**
- Define the canonical statuses: `RECEIVED`, `IN_PROGRESS`, `ON_HOLD`, `COMPLETED`, `DELIVERED`, `CANCELLED`.
- Add them to a seed script (see the seed script issue) and document them in the README.
- Decide and document which statuses count as "open" vs "closed" (e.g. `DELIVERED`/`CANCELLED` are terminal).

**Acceptance criteria:**
- Fresh database ends up with the canonical statuses after seeding.
- README documents the status lifecycle: Received → In Progress → Completed → Delivered.

## Service Orders

### Service orders list: search by partial tag number

**Labels:** `frontend`, `backend`, `service-orders`

**Context:** Tags look like `260004` (YY + running number). Operators remember the last digits, not the year prefix. The current filter only matches the exact full number.

**What to do:**
- **Contract first:** in `backend/src/openapi/openapi.yaml`, replace the `tagNo` (integer, exact) query param on `GET /service-orders` with `tagSearch` (string, partial match).
- Backend: match any tag whose digits contain the query (`tag_no::text ILIKE '%<q>%'`), keep ordering by `created_at DESC` so recent orders surface first. Typing `0004` must find `260004`.
- Frontend: replace the numeric "Tag #" filter with a debounced text field (`useDebounce` exists in `lib/hooks`).
- Regenerate the client: `cd frontend && npx orval`.

**Acceptance criteria:**
- Typing `0004` finds tag `260004`; typing `260004` also finds it.
- Results are ordered newest first; clearing the field restores the full list.

- Frontend: replace the "Payment status" filter with a "Status" dropdown whose options come from `GET /references/statuses` (hook `useGetReferencesStatuses` already exists). Orders with no status yet display as "Received".
- Keep payment status visible on the detail page only.

**Acceptance criteria:** Selecting "In Progress" lists only orders whose latest status is In Progress; the filter options are loaded from the API, not hard-coded.
